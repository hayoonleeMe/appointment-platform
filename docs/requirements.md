# 요구사항

## 운영 일정

### REQ-SCHED-001 기본 운영 일정

운영자는 반복되는 기본 운영 일정을 요일별로 설정한다. 초기 MVP에서는 하루에 하나의 연속된 운영 구간만 설정할 수 있다.

모든 운영 일정과 예약 시간은 `Asia/Seoul` 시간대를 기준으로 한다.

예:

- 월요일 10:00 ~ 18:00
- 수요일 휴무
- 목요일 10:00 ~ 20:00

운영 일정은 서비스별이 아니라 운영자에게 속한다.

## 예약 서비스

### REQ-SERVICE-001 예약 서비스 설정

운영자는 하나 이상의 예약 서비스를 등록할 수 있다. 각 서비스에는 다음 정보를 둔다.

- 서비스명
- 소요 시간
- 서비스 종료 후 준비 시간
- 예약 시작 간격
- 활성 상태

비활성 예약 서비스는 고객 예약 페이지 목록에서 숨기며 새 예약을 생성할 수 없다.

예약 시작 간격은 고객이 선택할 수 있는 시작 시각 사이의 간격이며, 서비스 소요 시간과는 별개다.

## 예약 가능 시간

### REQ-AVAIL-001 예약 가능 시간의 동적 계산

고객이 서비스와 날짜를 선택하면 시스템은 예약 가능한 시작 시각을 동적으로 계산한다. 미리 생성한 예약 슬롯은 저장하지 않는다.

계산에는 다음을 사용한다.

- 해당 요일의 기본 운영 일정
- 선택한 서비스의 소요 시간, 준비 시간, 예약 시작 간격
- 동일 운영자의 확정된 예약

### REQ-AVAIL-002 시작 후보 시간

시작 후보는 해당 요일의 운영 구간 시작 시각부터 예약 시작 간격 단위로 생성한다.

예를 들어 운영 구간이 10:20 ~ 18:00이고 예약 시작 간격이 60분이면 시작 후보는 10:20, 11:20, 12:20 순서다.

### REQ-AVAIL-003 예약 가능 조건

시작 후보는 다음 조건을 모두 만족할 때만 예약 가능하다.

- 과거 시간이 아니다.
- 서비스 소요 시간과 준비 시간을 포함한 전체 점유 시간이 운영 구간 안에 들어온다.
- 동일 운영자의 확정된 예약 점유 시간과 겹치지 않는다.

### REQ-AVAIL-004 준비 시간과 충돌 판정

서비스 시간이 50분이고 준비 시간이 10분이면 고객에게는 10:00 ~ 10:50으로 표시하더라도, 충돌 판단에서는 10:00 ~ 11:00을 점유한 것으로 본다. 서비스 종류가 달라도 같은 운영자의 점유 시간은 겹칠 수 없다.

운영 구간 종료 전 남은 시간이 필요한 전체 시간보다 짧으면 서비스 시간을 줄이지 않고 해당 시작 후보를 제공하지 않는다.

## 예약 생성

### REQ-BOOK-001 비회원 예약 정보

고객은 운영자의 예약 페이지에서 서비스와 예약 가능한 시작 시간을 선택한 뒤 이름과 전화번호를 입력해 비회원으로 예약한다.

### REQ-BOOK-002 예약 생성 시 재검증

예약 가능 시간 조회와 예약 생성 사이에 다른 고객이 먼저 예약할 수 있으므로, 조회 결과만으로 예약을 보장하지 않는다. 서버는 예약을 확정하기 전에 선택한 시간이 여전히 예약 가능한지 다시 검증한다.

## 예약 취소

### REQ-CANCEL-001 운영자 예약 취소

초기 MVP에서는 운영자만 확정된 예약을 취소할 수 있다. 취소된 예약의 점유 시간은 이후 예약 가능 시간 계산에서 제외한다.

고객의 예약 조회·취소, 예약 변경, 취소 안내는 MVP 이후 범위다.
