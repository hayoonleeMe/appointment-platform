# 유스케이스

이 문서는 MVP의 사용자 목표와 흐름을 정의한다. 상세 규칙과 완료 조건은 연결 요구사항을 원본으로 삼는다. 구현 이슈는 이 유스케이스를 기준으로 만들되, 복잡도와 의존성에 따라 하나의 유스케이스를 여러 이슈로 나눌 수 있다.

운영자는 공개 회원가입 후 로그인해 운영자 전용 기능을 이용한다. 고객은 MVP에서 비회원으로 예약하며, 고객 회원가입과 로그인은 MVP 이후 범위다.

## UC-AUTH-001 운영자 회원가입

- 행위자: 운영자
- 연결 요구사항: `REQ-AUTH-001`
- 목적: 예약 기능을 이용할 운영자 계정을 만든다.

### 기본 흐름

1. 운영자가 이름, 이메일, 비밀번호를 입력해 회원가입을 요청한다.
2. 시스템이 이메일의 사용 가능 여부를 확인한다.
3. 시스템이 활성 상태의 운영자 계정을 생성한다.

### 예외 흐름

- 이미 사용 중인 이메일이면 시스템은 계정을 생성하지 않고 회원가입할 수 없음을 안내한다.

## UC-AUTH-002 운영자 로그인

- 행위자: 운영자
- 연결 요구사항: `REQ-AUTH-002`, `REQ-AUTH-003`
- 목적: 운영자 전용 기능을 이용할 수 있도록 자신을 인증한다.

### 기본 흐름

1. 운영자가 이메일과 비밀번호를 입력한다.
2. 시스템이 등록된 활성 운영자 계정의 자격 정보와 일치하는지 확인한다.
3. 시스템이 운영자를 인증된 운영자로 식별한다.

### 예외 흐름

- 등록되지 않은 이메일, 일치하지 않는 비밀번호 또는 비활성 상태의 계정이면 시스템은 로그인을 완료하지 않는다.

## UC-OPERATOR-001 예약 유형 설정

- 행위자: 운영자
- 연결 요구사항: `REQ-TYPE-001`
- 목적: 고객이 예약할 예약 유형과 예약 방식을 등록하고, 예약 가능 여부를 관리한다.

### 기본 흐름

1. 운영자가 예약 유형과 예약 가능 일정을 입력한다.
2. 시스템이 예약 유형과 일정을 등록한다.
3. 운영자가 등록된 예약 유형의 활성 상태를 변경한다.
4. 시스템이 변경된 활성 상태를 저장한다.

## UC-OPERATOR-002 예약 유형 일정 변경과 날짜 예외 설정

- 행위자: 운영자
- 연결 요구사항: `REQ-TYPE-SCHEDULE-001`, `REQ-TYPE-SCHEDULE-002`
- 목적: 등록된 예약 유형의 반복 예약 가능 시간을 변경하고 특정 날짜 예외를 관리한다.

### 기본 흐름

1. 운영자가 예약 유형을 선택한다.
2. 운영자가 반복 일정과 특정 날짜 예외를 변경한다.
3. 시스템이 예약 유형의 일정 전체를 원자적으로 교체한다.

## UC-OPERATOR-003 그룹 수업 회차 생성과 취소

- 행위자: 운영자
- 연결 요구사항: `REQ-SESSION-001`, `REQ-SESSION-002`
- 목적: 그룹 수업 예약 유형의 특정 날짜·시각 회차를 만들고 필요하면 취소한다.

### 기본 흐름

1. 운영자가 그룹 수업 예약 유형, 미래의 시작 시각, 정원을 입력한다.
2. 시스템이 해당 날짜의 예약 유형 최종 예약 가능 시간 및 다른 예정 예약 세션과의 점유 시간 충돌을 검증한다.
3. 검증에 성공하면 예정 상태의 예약 세션을 생성한다.
4. 운영자가 예정된 예약 세션을 취소할 수 있다.
5. 시스템이 세션과 연결된 확정 예약을 모두 취소 상태로 변경한다.

### 완료 기준

- 1:1 예약 유형으로는 그룹 수업 예약 세션을 생성할 수 없다.
- 빈 그룹 수업 예약 세션도 같은 운영자의 시간을 점유한다.
- 취소된 예약 세션은 예약 가능 시간 계산에서 제외된다.

## UC-CUSTOMER-001 예약 페이지와 예약 유형 조회

- 행위자: 고객
- 연결 요구사항: `REQ-PAGE-001`, `REQ-TYPE-001`
- 목적: 특정 운영자의 예약 페이지에서 예약 유형을 고른다.

### 기본 흐름

1. 고객이 운영자의 예약 페이지에 접속한다.
2. 시스템이 해당 운영자의 활성 예약 유형 목록을 보여 준다.
3. 고객이 예약 유형과 날짜를 선택해 예약 가능 선택지 조회로 이동한다.

## UC-CUSTOMER-002 예약 가능 선택지 조회

- 행위자: 고객
- 연결 요구사항: `REQ-AVAIL-001`, `REQ-AVAIL-002`, `REQ-AVAIL-003`, `REQ-AVAIL-004`, `REQ-AVAIL-005`
- 목적: 선택한 예약 유형과 날짜에 예약할 수 있는 선택지를 확인한다.

### 기본 흐름

1. 고객이 활성 예약 유형과 날짜를 선택한다.
2. 선택한 유형이 1:1이면 시스템이 예약 유형의 최종 예약 가능 시간과 예약 세션을 기준으로 가능한 시작 시각을 동적으로 계산해 보여 준다.
3. 선택한 유형이 그룹 수업이면 시스템이 예정된 예약 세션의 시작·종료 시각과 잔여 좌석을 보여 준다.

## UC-CUSTOMER-003 1:1 비회원 예약 확정

- 행위자: 고객
- 연결 요구사항: `REQ-TYPE-001`, `REQ-BOOK-001`, `REQ-BOOK-002`, `REQ-AVAIL-003`, `REQ-AVAIL-004`
- 목적: 선택한 1:1 시작 시각에 이름과 전화번호로 예약한다.

### 기본 흐름

1. 고객이 1:1 예약 유형, 예약 가능한 시작 시각, 이름, 전화번호를 입력한다.
2. 시스템이 예약 생성 시점에 유형이 활성 상태이고 해당 시간이 여전히 가능한지 다시 검증한다.
3. 검증에 성공하면 정원 1의 예약 세션과 확정 예약을 함께 생성한다.

### 예외 흐름

- 다른 예약 세션이 먼저 생성되었거나 예약 유형이 비활성화되어 시간이 더는 예약 가능하지 않으면, 예약을 만들지 않고 고객에게 다시 선택을 요청한다.

## UC-CUSTOMER-004 그룹 수업 좌석 예약

- 행위자: 고객
- 연결 요구사항: `REQ-TYPE-001`, `REQ-AVAIL-005`, `REQ-BOOK-001`, `REQ-BOOK-003`
- 목적: 예정된 그룹 수업 예약 세션의 남은 좌석 하나를 예약한다.

### 기본 흐름

1. 고객이 그룹 수업 예약 유형과 날짜를 선택해 예약 세션을 고른다.
2. 고객이 이름과 전화번호를 입력한다.
3. 시스템이 예약 생성 시점에 유형이 활성 상태이고 세션이 예정 상태이며 잔여 좌석이 있는지 다시 검증한다.
4. 검증에 성공하면 해당 예약 세션에 확정 예약을 생성한다.

### 예외 흐름

- 다른 고객이 마지막 좌석을 먼저 예약했거나 세션이 취소되면, 예약을 만들지 않고 고객에게 다른 회차를 선택하도록 안내한다.

## UC-OPERATOR-004 예약 현황 조회와 예약 취소

- 행위자: 운영자
- 연결 요구사항: `REQ-RESERVATION-001`, `REQ-CANCEL-001`
- 목적: 예약 현황을 확인하고 필요하면 확정 예약을 취소한다.

### 기본 흐름

1. 운영자가 자신의 예약 현황을 조회한다.
2. 시스템이 확정 예약과 취소 예약을 보여 준다.
3. 운영자가 확정 예약을 선택해 취소한다.
4. 시스템이 예약 상태를 취소로 변경한다.
5. 취소된 예약이 1:1 예약이면 연결된 예약 세션도 취소한다.
